TemporalCI is a **proof of concept for CI orchestration** using [Temporal](https://temporal.io/) and Kubernetes. A Go worker coordinates repository checkout, build steps, reporting, and cleanup through Temporal workflows.

## What It Explores

Temporal records workflow decisions and activity results, providing a history that helps inspect orchestration failures. TemporalCI explores how that model fits CI workloads.

| Capability | Current implementation |
|---|---|
| Workflow history | Temporal stores decisions and activity results |
| Retries | Per-activity policies; regular build steps have one attempt |
| Inspection | Temporal UI exposes execution history; log storage requires configuration |
| Kubernetes execution | Build pods run steps; cluster capacity and scheduling remain operator concerns |

## How It Works

1. You push code to GitHub
2. GitHub sends a webhook to TemporalCI
3. TemporalCI starts a Temporal workflow
4. The workflow runs each CI step in an isolated K8s pod
5. The worker attempts GitHub reporting when credentials and event metadata are available

<Aside type="caution">
Workflow replay does not restore worker-local checkout files or running commands. Restart recovery and cleanup need further validation. Use disposable infrastructure and repositories you trust.
</Aside>

## Who It's For

TemporalCI is for developers who want to evaluate:

- Temporal as a CI orchestration engine
- Kubernetes build pods and declarative pipeline configuration
- Workflow history, retries, and cancellation boundaries

It is not a production-ready hosted service or a hardened multi-tenant executor.

## Tech Stack

| Component | Technology |
|-----------|-----------|
| Language | Go |
| Orchestration | Temporal (self-hosted) |
| Execution | Kubernetes pods |
| Infrastructure | Experimental EKS Auto Mode / minikube |
| Deployment | Helm + ArgoCD |
| Database | PostgreSQL subchart in the checked-in local/EKS values; optional RDS configuration |
